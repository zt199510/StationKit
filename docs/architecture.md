# 架構說明

## 分層

```text
            samples / 具體設備（例如 PCB 雙工位曝光機、鎖螺絲機）
                 │
     ┌───────────┼───────────────┐
     ▼           ▼               ▼
  Stations     Safety     Motion.Simulation / 廠商適配器
     │           │               │
     ▼           └──────┬────────┘
  Alarms                ▼
                  Abstractions
```

- **Abstractions 不放任何業務實體**：沒有「孔位」「圖紙」「拍照」這類概念。業務模型放在具體設備的項目裡。
- **廠商 SDK 只出現在適配器項目中**：業務代碼不允許出現任何 `dmc_*`、`smc_*`、`GT_*` 這類調用。
- **沒有任何一層依賴 UI**：界面通過事件和快照讀取狀態。

## 關鍵決策

### 1. 運動 Task 在到位時才完成

很多項目的 `MoveAsync` 在指令下發後就返回，然後在業務代碼裡到處輪詢 `IsDone`。這導致「等待到位」的邏輯分散在各處，超時和報警處理也各寫各的。StationKit 規定運動方法在到位時完成，在報警時拋出 `MotionFaultException`，業務代碼只需要 `await`。

下發和等待可以分開：不 `await` 就是只下發，之後再 `await` 返回的 `Task`。多軸同時運動用 `MotionGroup.MoveAllAsync`，不要直接 `Task.WhenAll`：`WhenAll` 會等所有軸各自走完才報故障，X 已經報警了，Y 還在往目標走。`MotionGroup` 在任何一軸故障時立即停下其餘軸，只拋出引發停止的那個故障。

### 2. 取消不能晚於下發

`MoveAbsoluteAsync` 在持鎖狀態下先檢查取消令牌，再下發指令。否則會出現這種事故：操作員按下停止，緊接著一條已經「被取消」的運動指令還是下發到了控制卡。指令一旦下發，取消就會先停軸，再拋出 `OperationCanceledException`。

### 3. 點動：最容易出事故的操作，單獨設計

點動沒有目標位置，人按著就一直走，所以拆成三層：

| 層 | 職責 |
|---|---|
| `IAxis.JogAsync` | 裸的速度模式點動。取消令牌表示「鬆開按鈕」：減速停止、停穩後**正常完成**（這是唯一不拋 `OperationCanceledException` 的取消） |
| `GuardedAxis.JogAsync` | 已回零：不用速度模式，改為**點位運動到軟限位邊界**，鬆開即停，卡上軟限位配錯也越不過邊界。未回零：坐標不可信，只允許不超過 `UnhomedJogMaxVelocity` 的低速，未配置則禁止 |
| `JogSession` | 看門狗。界面按住期間定時 `KeepAlive()`，超時沒收到就自動停軸並以故障結束 |

看門狗是為了防一種很常見卻很少有人處理的情況：窗口失焦、彈出對話框、觸摸屏誤觸、UI 線程卡住時，`MouseUp` 根本不會觸發，只靠鬆開事件停軸，軸會一直走到限位。

寸動（固定距離）用 `MoveRelativeAsync` 擴展方法：換算成絕對目標後走 `MoveAbsoluteAsync`，經過 `GuardedAxis` 時同樣受軟限位檢查。

### 4. 安全初始化是全有或全無

```text
校驗全部軸 ──失敗──▶ 拋出，沒有寫入任何參數
     │
寫入全部軸
     │
回讀核對 ───不一致──▶ 拋出，沒有任何軸被使能
     │
使能全部軸 ──中途失敗──▶ 已使能的軸全部失能，然後拋出
```

回讀這一步很重要：控制卡返回「設置成功」，不代表參數真的生效了，比如寫錯了軸號，或者固件版本不支持某個參數。

### 5. 共享資源：不確定就保持佔用

`ResourceArbiter.UseAsync` 在持有期間捕獲到**任何**異常（包括操作員按停止），都會把資源標記為「不確定」並保持佔用。其他工站只能等到超時並報警，直到人工確認現場後調用 `ResetUncertain`。

代價是停機後恢復要多一步人工操作。換來的是：系統永遠不會讓一個工站開進另一個工站「可能還在」的區域。

### 6. 暫停只在安全點生效

`Pause()` 只把狀態置為 `Pausing`。工站要運行到下一個 `CheckpointAsync()` 才真正進入 `Paused`。安全點由工藝決定：只放在機構處於安全位置、而且不持有共享資源的地方。界面上應該區分「暫停中」和「已暫停」。

### 7. 報警永不拋異常

`AlarmCenter.Raise` 遇到未登記的代碼時，會按 `SYS-000`（故障級）處理並保留原代碼，而不是拋出異常。報警路徑本身出錯，會掩蓋真正的故障。

## 已知限制

- **互鎖是「檢查後執行」**：`GuardedAxis` 在下發前檢查互鎖，但檢查和運動之間，其他軸的狀態可能改變。涉及多軸碰撞時，要同時用資源租約保證互斥，並保留硬件互鎖。
- **模擬軸把減速停止當作立即停止**：位置凍結在停止時刻，沒有模擬減速段。
- **工站故障不會連帶停止其他工站**：其他工站在需要共享資源時會因為超時而停下。如果需要全線急停，應由上層訂閱報警並統一處理。
